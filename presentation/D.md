# D 파트 — 질문을 이해하고, 근거로 설명하는 AI 분석 (3분 · 3장)

> **한 문장:** AI에게 숫자 계산을 맡기지 않고, **코드가 계산한 결과를 AI가 이해하기 쉽게 설명**하도록 만들었습니다.

## 1. 발표 슬라이드 3장

| # | 제목 | 발표 핵심 |
|---|---|---|
| 1 | **자연어 질문을 계산 가능한 요청으로 바꾼다** | 사용자가 “매출이 가장 높은 상품은?”, “광고 효율이 낮은 플랫폼은?”처럼 평소 말로 질문하면, 질문의 지표·대상·기간·정렬 조건을 찾고 서버가 다시 검증한 뒤 계산합니다. |
| 2 | **여러 지표를 함께 보는 상품 진단도 지원한다** | “저평가된 상품”, “관리할 상품”, “광고비는 늘었는데 성과가 떨어진 상품”처럼 한 지표만으로 답하기 어려운 질문은 **매출·주문·판매량·광고비·광고매출·ROAS 변화**를 함께 계산해 기회/관리 후보를 찾습니다. |
| 3 | **AI가 임의로 숫자를 만들지 못하게 했다** | 순위·점수·수치는 pandas가 계산하고, 서버가 근거까지 확인합니다. 데이터에 없는 원가·재고·경쟁사 정보는 추정하지 않습니다. AI 호출이 실패해도 이미 계산한 KPI·차트는 유지됩니다. |

### 슬라이드 2에서 보여줄 흐름

```text
사용자 질문
"판매 추세로 볼 때 주목할 상품은?"
        ↓
질문 유형 확인
        ↓
상품별 여러 지표 계산
매출 · 주문 · 판매량 · 광고비 · 광고매출 · ROAS
        ↓
기회 상품 / 관리 필요 상품 후보 선정
        ↓
계산된 근거만 문장으로 설명
```

> 발표에서는 “저평가 상품”을 **시장가치 평가**라고 말하지 않고,  
> **“현재 판매·광고 데이터에서 추가로 볼 가치가 있는 기회 상품 후보”**라고 설명합니다.

## 2. 내가 구현한 기술 스택

| 기술 | 어디에 썼나 |
|---|---|
| **Python** | 질문 처리와 분석 로직 |
| **pandas** | 상품별 매출·주문·광고 성과 계산, 순위·점수 산출 |
| **Pydantic** | AI가 만든 분석 계획과 입력 조건 검증 |
| **OpenAI API** | 일반 자연어 질문을 분석 조건으로 해석하고 근거를 선택 |
| **FastAPI 연동** | 질문 → 계산 → 설명 결과를 기존 `/api/analyze` 흐름에 연결 |
| **pytest** | 잘못된 숫자·조건 누락·근거 변조를 자동 테스트 |
| **TypeScript / Next.js** | 상품 진단 결과표의 핵심 열과 한글 표시 보완 |

### 기술 구현을 더 쉽게 말하면

```text
일반 질문
→ AI가 질문 뜻을 구조화
→ pandas가 계산
→ 서버가 숫자·근거 검증
→ AI가 설명

복합 상품 진단
→ 정해진 질문 패턴으로 진단 종류 확인
→ pandas가 여러 지표를 함께 계산
→ 서버가 순위·점수·근거 확정
→ 고정된 근거 문장으로 설명
```

**중요:** 복합 상품 진단 경로는 결과의 일관성을 위해 **LLM을 추가 호출하지 않습니다.**

## 3. 이번에 추가한 복합 상품 진단

### 기회 상품 후보

판매가 성장하고 있고, 확인 가능한 광고 효율도 상대적으로 양호한 상품을 찾습니다.

예:
- “판매 추세로 볼 때 저평가된 상품은?”
- “더 키워볼 만한 상품은?”
- “판매는 오르는데 광고를 덜 쓰고 있는 상품은?”

### 관리 필요 상품

성과 하락이나 광고비 대비 효율 저하 신호가 있는 상품을 찾습니다.

예:
- “관리해야 할 상품은?”
- “광고비는 늘었는데 성과가 떨어진 상품은?”
- “광고 효율이 나빠지는 상품은?”

### 판단에 사용하는 대표 데이터

```text
매출 변화
주문 / 판매량 변화
광고비 변화
광고매출 변화
ROAS와 ROAS 변화
+ 스마트스토어는 전환율·환불률도 가능한 범위에서 사용
```

점수는 **성공 확률이 아니라, 실제 데이터에서 확인된 신호의 개수**입니다.

# 6. 예상 질문과 답변

| 예상 질문 | 짧은 답변 |
|---|---|
| **AI가 엑셀 숫자를 직접 계산하나요?** | 아닙니다. 숫자와 순위는 pandas가 계산하고, AI는 질문 해석과 설명을 담당합니다. |
| **왜 그냥 GPT에게 엑셀 전체를 주고 분석시키지 않았나요?** | 같은 데이터에서 매번 같은 숫자가 나오게 하고, AI의 계산 실수나 없는 사실 생성을 줄이기 위해 계산과 설명을 분리했습니다. |
| **“저평가 상품”은 어떤 기준인가요?** | 시장가치 평가가 아닙니다. 매출·주문·판매량 성장과 ROAS 등 현재 데이터에서 확인되는 신호를 조합한 **기회 상품 후보**입니다. |
| **상품 진단 점수가 높으면 무조건 좋은 상품인가요?** | 아닙니다. 점수는 성공 확률이 아니라 확인된 데이터 신호의 개수입니다. 재고·마진 등은 별도로 봐야 합니다. |
| **여러 조건이 들어간 질문도 처리하나요?** | 지원하는 조건은 모두 보존합니다. 예를 들어 “광고비는 늘었는데 성과가 떨어진 상품”이면 두 조건을 모두 만족해야 결과에 포함됩니다. |
| **왜 복합 상품 진단에서는 GPT를 안 쓰나요?** | 순위와 판단 기준을 매번 동일하게 유지하기 위해 정해진 규칙과 pandas 계산으로 처리합니다. 자연어 생성이 꼭 필요하지 않은 부분은 AI에 맡기지 않았습니다. |
| **일반 질문에서는 OpenAI를 어디에 쓰나요?** | 사용자의 문장을 매출·ROAS·상품별·월별 같은 계산 가능한 분석 계획으로 바꾸고, 계산된 근거 중 무엇을 설명할지 선택하는 데 사용합니다. |
| **데이터가 한 달밖에 없으면 추세 분석도 하나요?** | 하지 않습니다. 기준 월과 달력상 바로 전월, 최소 두 달의 동일 상품 자료가 있어야 합니다. |
| **7월과 9월만 있으면 비교하나요?** | 아니요. 9월의 전월은 8월이므로 8월 자료가 없으면 전월 비교를 하지 않습니다. |
| **새로 생긴 상품은 전월 매출을 0으로 보고 성장률을 계산하나요?** | 아닙니다. 없는 상품을 0으로 만들면 성장률이 왜곡되기 때문에 비교 후보에서 제외합니다. |
| **판매 파일과 광고 파일의 상품은 어떻게 연결하나요?** | 확인 가능한 동일 상품 ID만 연결합니다. 쿠팡은 동일 옵션 ID만 연결하고, 네이버 광고 소재 ID와 스마트스토어 상품 ID는 억지로 합치지 않습니다. |
| **데이터에 없는 원가·재고·마진도 추천에 쓰나요?** | 아닙니다. 없는 정보는 추정하지 않고 한계나 추가 확인 항목으로 안내합니다. |
| **AI가 틀린 근거나 숫자를 설명하려 하면요?** | 서버가 순위·점수·reason code·기간·숫자가 서로 맞는지 검증합니다. 맞지 않으면 설명을 생성하지 않습니다. |
| **AI API가 장애 나면 서비스가 멈추나요?** | KPI와 차트 계산은 AI와 분리돼 있어 유지됩니다. 복합 상품 진단은 LLM을 호출하지 않아 그 경로도 별도로 동작합니다. |
| **3개월 이상 올리면 장기 추세를 보나요?** | 현재 MVP 상품 진단은 최신 기준 월과 바로 전월 두 달을 비교합니다. 장기 추세나 미래 예측은 다음 확장 영역입니다. |
| **미래 매출도 예측할 수 있나요?** | 현재는 하지 않습니다. 업로드된 과거·현재 데이터를 설명하고 비교하는 데 집중했습니다. |
| **테스트는 어떻게 했나요?** | 기존 기능 회귀를 포함해 비유료 테스트 624개가 통과했고, 그중 새 상품 진단 테스트가 91개입니다. 데스크톱과 모바일에서도 실제 API 흐름을 확인했습니다. |
| **원본 엑셀 전체가 OpenAI로 가나요?** | 일반 AI 설명 경로에서는 서버가 계산한 결과를 바탕으로 AI를 사용하며 원본 엑셀 전체를 그대로 보내 분석시키는 구조가 아닙니다. 복합 상품 진단은 OpenAI를 추가 호출하지 않습니다. |
