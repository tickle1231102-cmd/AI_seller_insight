## 2. 예상 질문 3개와 답

| 질문 | 답 |
|---|---|
| 이상한 파일을 올리거나 AI가 고장 나면 서비스가 멈추지 않나요? | 멈추지 않습니다. 파일은 서버가 먼저 검사해서 개수·크기·형식·빈 파일·빠진 컬럼·손상 파일 등을 오류 코드 17개로 구분해 안내합니다. 예를 들어 깨진 엑셀은 서버 오류(500)가 아니라 "파일을 읽을 수 없습니다"로 알려 줍니다 (#20). AI는 호출마다 30초 제한이 있고, 실패해도 이미 계산한 KPI와 차트는 그대로 보여 주고 AI 영역에만 다시 시도 안내를 띄웁니다. 실제 배포 서버에서 이런 상황 21가지를 직접 시험했습니다. |
| 무료 서버인데, 시연 중에 느려지거나 배포가 실패하면 어떻게 되나요? | Render 무료 플랜은 한동안 요청이 없으면 잠들어서 첫 요청이 50초 이상 걸릴 수 있습니다. 그래서 발표 30분 전에 `/health`를 열어 깨워 둡니다. 배포는 코드가 합쳐지면 자동으로 요청되는데, 새 버전이 완전히 올라갈 때까지 이전 버전이 계속 돌아서 사이트가 멈추지 않습니다. 배포에 실패해도 이전 버전이 유지되고, 실제 반영 여부는 Render Events에서 확인합니다. 지금까지 배포 10번 모두 성공했습니다. |
| 네 명이 따로 만든 코드를 어떻게 하나로 맞췄나요? | 서로 주고받는 데이터 모양을 공통 계약 문서(`shared/contracts/`)로 먼저 정하고, 네 명 모두 이 문서를 기준으로 코드를 만들었습니다. 예를 들어 계산 결과는 `kpis`·`comparison`·`signals` 같은 정해진 이름과 형식으로만 주고받고, 오류도 항상 `code`·`message`·`details` 모양으로 보냅니다. 서버는 정해진 순서대로 C의 계산과 D의 AI를 부르고, 결과를 하나의 응답으로 묶어 화면에 보냅니다. 약속을 바꿀 때는 작성자 말고 나머지 세 명이 모두 동의해야 하고, 실제로 이 방식으로 계약을 두 번 바꿨습니다 (#20, #28). |
