## 반영 내용

1. OpenAI에 요청하는 `InsightContent`는 설명 필드 5개만 포함한다. `status`, `plan`, `answer`, `reason`은 모델 출력 대상이 아니다.
2. 최종 응답은 서버가 새로 구성한다. 질문이 없으면 `plan=null`, `answer=[]`이며, 질문이 있으면 호출자가 넘긴 계획·계산 결과를 유지한다. 유효한 설명의 상태는 서버가 `ok`로 정한다.
3. `evidence`의 근거 없는 숫자는 기존 계약대로 항목을 제거한다. `summary`, `checks`, `actions`, `limitations`에 근거 없는 숫자가 있으면 설명 전체를 `llm_error`로 처리한다. 원래 계획·답과 KPI는 유지한다.
4. 쉼표, Unicode 마이너스, 소수점, 지수 표기 숫자를 검사한다. 계획의 `limit`는 판매 수치의 근거로 인정하지 않는다.
5. 자료 안의 문장을 지시로 따르지 않고, 외부 지식으로 수치·원인을 채우지 않도록 프롬프트를 보강했다.

## PR #10 A 리뷰 보완

리뷰: https://github.com/tickle1231102-cmd/AI_seller_insight/pull/10#pullrequestreview-5348535346

- 날짜를 일반 숫자와 분리한다. 입력에 있는 `YYYY-MM` 및 `YYYY년 M월`은 연·월 쌍으로 검증하고, `N월`·`YYYY년`도 실제 입력 기간에 있는 값만 허용한다. 날짜 하이픈을 음수로 읽지 않으며, 날짜·상품 ID의 숫자는 판매 수치의 허용 목록에 넣지 않는다.
- 원/천 원/만 원/억 원을 원 단위로 정확히 정규화한다. Decimal 비교로 반올림 없이 같은 금액만 허용한다. 복합 단위(`1억 2,600만 원`)는 지원하지 않으며, 원문 원 단위 또는 단일 단위를 사용하도록 프롬프트에 명시한다.
- C의 ROAS·증감률은 이미 퍼센트 단위다. 100배 변환을 추가하지 않았고 `%`와 `%p`도 구분한다.
- `checks`/`actions`/`limitations`의 1–10 번호 목록 및 명시적 확인·검토 항목 개수만 설명 구조로 허용한다. `판매량 3개`, `주문 2건` 같은 데이터 주장은 예외가 아니다. 상위 N개/순위 표현은 실제 `answer` 행 수를 넘을 수 없다.
- `14.2%p 하락`처럼 부호 없는 감소량은 입력의 음수 변화량과 대조한다. 모든 수치를 절댓값으로 비교하지 않으므로, `+14.2%p`나 `-28%`처럼 원래 부호를 바꾼 주장은 차단한다.
- 근거 없는 evidence 제거, 다른 설명 필드의 `llm_error`, 서버가 정하는 상태·plan·answer 보호는 유지한다.
- 최신 main의 팀 문서 변경만 병합했다. B/C 구현·공통 계약 내용·프론트엔드를 D 수정으로 변경하지 않았다.

## 한계와 별도 작업

- 숫자 검증은 입력에 해당 숫자가 존재하는지 검사한다. 플랫폼·지표의 의미가 정확히 연결됐는지, 숫자가 없는 원인 추론까지 올바른지는 보장하지 않는다. 전체 WU-AI-04 의미·품질 검증은 별도다.
