# D AI 활용 대표 사례

최신화: 2026-09-30 · 구현29a90ea/검증3054ea8. 현재 단일 검증은 D_WEDNESDAY_STATUS.md 참고.

담당: D(AI / Insight / AI QA)

대상: `feat/ai-evidence-grounding` / PR #18 후속 검증

이 문서는 AI가 코드를 대신 계산한 사례가 아니라, **자연어를 제한된 분석 계획으로 바꾸고 검증된 계산 결과만 설명하도록 개선한 과정**을 기록한다. 실제 API 키와 사용자 데이터는 포함하지 않는다.

## 사례 1 — 질문 조건을 임의로 버리지 않도록 Planner 보강

- 문제: 월 맥락 없이 상대 월 조건을 버리거나 상위100개를 기본값으로 축소할 수 있었다. #23 확장 뒤 기존 D 정책을 두면 정상 증감/스토어 질문까지 막힐 수 있었다.
- 개선: 명시 조건과 업로드 월을 결정적으로 해석해 모델 계획과 대조한다. M월/이번 달/지난달은 맥락이 있을 때만 수용하고 없는 월을 대체하지 않는다. 표현 못하는 조건은 unrepresented_constraints로 재확인한다.
- 결과: 최신 고정40문항에서 지원26/26·미지원14/14. 월 표현·24개 지표 조건과 기존 필터/범위/개수 보호를 함께 검증했다. 과거 결과와 합산하지 않는다.
- 한계: 개발에 사용한 고정 회귀 세트의 결과이며 임의 자연어 전체에 대한 100% 정확도를 뜻하지 않는다.

## 사례 2 — 자유 문장 대신 검증된 근거 ID 선택

- 문제: 입력에 같은 숫자가 존재하기만 하면 LLM이 다른 기간·플랫폼·지표에 붙여 설명할 가능성이 있었다. 숫자만 비교하는 후처리로는 의미 연결을 완전히 보장할 수 없었다.
- 개선: 서버가 계산 결과를 `출처 경로 + 기간 + 대상 + 지표 + 값 + 단위`로 묶은 근거 목록으로 만든다. LLM은 `summary_fact_ids`, `evidence_fact_ids`, `check_ids`, `action_ids`만 선택하고, 최종 한국어 문장은 서버가 렌더링한다.
- 결과: 정상, 한 달 자료, ROAS 계산 불가, 특정 질문 결과, 불연속 월, 상품명 지시문, 신호 없음, 실제 주문 0의 8개 시나리오가 실제 `gpt-6-luna` 호출에서 정상 처리됐다. 같은 범위의 계산값이 서로 다른 1개 시나리오는 모델 호출 전에 `inconsistent_analysis_results`로 차단됐다.
- 한계: 근거는 현재 계산 결과 경로를 가리키며 원본 엑셀의 정확한 셀 위치까지 추적하지 않는다.

## 사례 3 — 모델 실패·주입 시 계산 결과 보호

- 문제: 모델 응답에 `status`, `plan`, `answer`, `reason` 또는 임의 수치·원인 문장이 섞이면 API 결과가 오염될 수 있었다.
- 개선: 공개 응답의 상태와 계산 결과는 서버가 소유한다. 모델이 반환한 메타데이터와 자유 문장은 무시하고, 허용 목록에 없는 근거·점검·행동 ID는 차단한다. 네트워크·검증 실패도 정규화된 `llm_error`로 바꾼다.
- 결과: 최신 비유료493개·새 채팅 실제 API 라우트7개 통과. 공개 fixture의 KPI·비교·신호·store·질문 답을 보존했다. 키 없음·공급자 오류·잘못된 출력 경로는 모킹 회귀로 확인했다. 별도 실행 수는 합산하지 않는다.
- 한계: 9월 30일 기존 배포 화면의 일시적 `llm_error` 응답 모의에서 KPI·차트 유지와 AI 오류 안내를 확인했다. 실제 공급자 장애를 유발한 테스트가 아니며, PR #18 개선본 재배포 후 검증은 별도다.

## 공통 검증 원칙

- 숫자 계산은 C의 pandas 코드가 수행하고, LLM은 질문 구조화와 근거 우선순위 선택만 담당한다.
- 공개 fixture만 실제 API에 전송했다.
- 실제 키는 로컬 `.env`에서만 읽고 출력·복사·커밋하지 않았다.
- 서로 다른 테스트 실행의 통과 수는 합산하지 않는다.
