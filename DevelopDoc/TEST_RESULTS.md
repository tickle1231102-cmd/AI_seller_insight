## 4. KPI 수기 검산 (완료 조건 4)

- 합성 fixture 기준: 쿠팡 2026-09 합계를 손으로 더해 `expected_kpis.json` 과 대조 — 매출 8,000,000 · 주문 520 · 광고비 1,200,000 · 광고매출 3,500,000 · ROAS 291.7 % 일치. 전체 KPI 는 `test_analysis.py` 가 정답 파일과 비교하고, 배포 서버 `/api/analyze` 결과도 정답과 일치(9/29 확인).
- **실제 형식에 가까운 샘플 대조 (9/30, D 가 준 4개 파일):** 4개 모두 공식 도움말·화면 지표를 바탕으로 만든 합성 샘플이라(네이버 광고 파일의 README 에 명시) 실제 내보내기와 같다는 보장은 없다. #38 전에는 스마트스토어 판매 분석만 통과하고 나머지 3종은 `UNKNOWN_PLATFORM` 이었다. #38 이후에는 4종을 모두 읽고, **원본 엑셀을 pandas 로 직접 합산**(앱 코드를 쓰지 않은 독립 계산)한 값과 앱 결과를 비교했다 (`a319813`, 4개 파일 + 2026-09):

  | 파일 | 원본 합계 (독립 계산) | 앱 결과 |
  |---|---|---|
  | 쿠팡 판매 지표 (옵션 단위) | 매출 51,386,270 · 주문 2,283 | 일치 |
  | 쿠팡 광고 리포트 | 광고비 6,336,528 · 총 전환매출액(14일) 34,966,700 → ROAS **551.8%** | 일치 |
  | 네이버 쇼핑검색광고 소재 보고서 | 총비용 3,048,563 · 총 전환매출액 10,909,500 → ROAS **357.9%** (월은 `일별` 컬럼, 2026-09) | 일치 |
  | 네이버 스마트스토어 판매 분석 | 상품 행 순매출 2,115,400 (월 요약 행과 같음) | 일치 |

  4개를 함께 올리고 2026-09 를 입력했을 때 합산 매출 53,501,670, ROAS 488.8% 다.
- **쿠팡 광고매출은 14일 기준이다.** 광고 리포트에 1일·14일 두 종류가 있고, 구현에서 14일을 골랐다 (팀 합의 사항은 아니다). 같은 파일에서 ROAS 가 14일 **551.8%**, 1일 **417.9%** (전환매출 26,483,000) 로 크게 달라지므로 ROAS 를 말할 때 기준을 함께 적는다.
- **기간:** 쿠팡 판매·광고 파일에는 기간 정보가 없다. #38 에서는 같이 올린 파일이 모두 한 월일 때만 그 월을 쓰고, 없거나 여러 월이면 `INVALID_PERIOD` 다. [#40](https://github.com/tickle1231102-cmd/AI_seller_insight/pull/40) 이 머지되면 추정 없이 사용자가 월을 직접 입력한다.
- **찾아 고친 문제:** 스마트스토어 판매 분석 파일에는 기간 요약 행과 일자별 `전체` 행이 상품 행과 섞여 있다. 그대로 더하면 매출이 정답의 3배(6,346,200 → 정답 2,115,400)가 되고 `전체` 가 상품으로 나왔다. 같은 월에 상품 행이 있을 때 그 월의 `전체` 행을 빼도록 고쳤고(`normalize._parse`), 수정 뒤 주문 104·방문 1,045·매출 2,115,400 이 파일의 월 요약 행과 일치한다. 오류 행 번호는 파일 기준을 유지한다. 상품 행이 없는 월의 `전체` 행은 대체할 데이터가 없으므로 남긴다(D 리뷰로 발견: 처음에는 파일 전체를 기준으로 판단해, 8월 상품 행 + 9월 `전체` 행만 있는 파일에서 9월 데이터가 사라졌다 → 월별 판단으로 수정, 회귀 테스트 추가). 한 월 안에서 월 요약 행과 일자별 `전체` 행만 있는 파일은 두 행이 겹칠 수 있는 한계가 남는다.
- **남은 한계:** 판매 파일과 광고 파일의 상품 ID 가 달라 **상품 단위로는 합쳐지지 않는다.** 플랫폼·월 합계는 정확하지만 "상품별 ROAS" 같은 질문은 한 상품의 판매와 광고가 다른 행으로 나뉘어 어긋날 수 있다 (향후 과제 [#32](https://github.com/tickle1231102-cmd/AI_seller_insight/issues/32)). 팀 결정 이력: [#21](https://github.com/tickle1231102-cmd/AI_seller_insight/issues/21) 에서 입력을 팀 템플릿으로 두고 한계를 명시하기로 했고, 이후 #38 이 실제 내보내기 4종 지원으로 확장했다.

### 4-1. 계산 정확성 재확인 (FINAL_CHECKLIST 3장, 9/30)
