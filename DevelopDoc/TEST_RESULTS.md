## 4. KPI 수기 검산 (완료 조건 4)

- 합성 fixture 기준: 쿠팡 2026-09 합계를 손으로 더해 `expected_kpis.json` 과 대조 — 매출 8,000,000 · 주문 520 · 광고비 1,200,000 · 광고매출 3,500,000 · ROAS 291.7 % 일치. 전체 KPI 는 `test_analysis.py` 가 정답 파일과 비교하고, 배포 서버 `/api/analyze` 결과도 정답과 일치(9/29 확인).
- **실제 형식에 가까운 샘플 대조 (9/30, D 가 준 4개 파일):** 4개 모두 공식 도움말·화면 지표를 바탕으로 만든 합성 샘플이라(네이버 광고 파일의 README 에 명시) 실제 내보내기와 같다는 보장은 없다. 현재 코드로 읽어 본 결과:

  | 파일 | 결과 | 이유 |
  |---|---|---|
  | 네이버 스마트스토어 판매 분석 | 통과 (`naver_store`) | 아래 "찾아 고친 문제" 참고 |
  | 쿠팡 판매 리포트 (옵션 단위) | `UNKNOWN_PLATFORM` | 5개 지표 중 `주문`·`판매량`만 일치. 매출은 `매출(원)`, 광고 컬럼 없음 |
  | 네이버 쇼핑검색광고 리포트 | `UNKNOWN_PLATFORM` | `광고비용`↔`총비용`, `전환매출`↔`총 전환매출액`. 판매 컬럼 없음 |
  | 쿠팡 광고 리포트 | `UNKNOWN_PLATFORM` | `광고비`만 일치. 매출은 `총 전환매출액(1일)`·`(14일)` 두 종류, 광고집행 옵션ID 단위 |

- **찾아 고친 문제:** 스마트스토어 판매 분석 파일에는 기간 요약 행과 일자별 `전체` 행이 상품 행과 섞여 있다. 그대로 더하면 매출이 정답의 3배(6,346,200 → 정답 2,115,400)가 되고 `전체` 가 상품으로 나왔다. 같은 월에 상품 행이 있을 때 그 월의 `전체` 행을 빼도록 고쳤고(`normalize._parse`), 수정 뒤 주문 104·방문 1,045·매출 2,115,400 이 파일의 월 요약 행과 일치한다. 오류 행 번호는 파일 기준을 유지한다. 상품 행이 없는 월의 `전체` 행은 대체할 데이터가 없으므로 남긴다(D 리뷰로 발견: 처음에는 파일 전체를 기준으로 판단해, 8월 상품 행 + 9월 `전체` 행만 있는 파일에서 9월 데이터가 사라졌다 → 월별 판단으로 수정, 회귀 테스트 추가). 한 월 안에서 월 요약 행과 일자별 `전체` 행만 있는 파일은 두 행이 겹칠 수 있는 한계가 남는다.
- **남은 한계 (구조 차이):** 쿠팡은 판매 리포트(옵션 단위)와 광고 리포트(일별·광고집행 옵션ID 단위)가 별개 파일이고 한 파일에 5개 지표가 있는 리포트는 찾지 못했다. 컬럼명 별칭만으로는 해결되지 않고 두 파일을 합치는 기능이 필요하다. 팀 결정 사항: (1) 입력을 "팀 정의 템플릿"으로 두고 한계로 명시 / (2) 컬럼 별칭 추가 / (3) 판매+광고 병합.
