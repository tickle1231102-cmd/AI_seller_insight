# PRD — Seller Insight AI

| 항목 | 내용 |
|---|---|
| 문서 | 제품 요구 사항 (Product Requirements Document) |
| 주 담당 | A (Frontend) + D (AI) |
| 범위 | MVP (5일 해커톤) |

---

## 1. 제품 개요

여러 판매·광고 플랫폼에서 내려받은 Excel/CSV 데이터를 통합하고, 매출·주문·광고비·광고매출·ROAS 등의 KPI를 계산해 플랫폼별·기간별 성과를 비교하며, AI가 **데이터 기반 원인 후보와 다음 행동을 제안**하는 서비스.

## 2. 문제 정의

| 문제 | 현재 상황 |
|---|---|
| 데이터 분산 | 쿠팡·네이버 등 플랫폼마다 별도 파일로 내려받음 |
| 컬럼 불일치 | 같은 의미의 지표가 플랫폼마다 다른 이름 (예: `총매출` vs `판매금액(순)`) |
| 수작업 계산 | ROAS, 전월 대비 증감률을 엑셀에서 직접 계산 |
| 해석의 어려움 | 숫자가 바뀐 이유와 다음 행동을 감으로 판단 |

## 3. 목표 사용자

- 2개 이상의 온라인 판매 플랫폼을 운영하는 소규모 셀러
- 플랫폼 광고를 집행하며 광고 효율(ROAS)을 관리해야 하는 운영 담당자
- 데이터 분석 도구 사용 경험이 적은 사용자

## 4. 목표 (Goals)

1. 여러 플랫폼 파일을 올리면 **1분 이내**에 통합 KPI를 확인할 수 있다.
2. 전월 대비 변화와 플랫폼별 성과 차이를 **한 화면**에서 비교할 수 있다.
3. 자연어 질문으로 원하는 분석 결과를 얻을 수 있다.
4. AI 설명은 **계산된 숫자에만 근거**하며, 데이터에 없는 원인을 단정하지 않는다.

### Non-Goals (MVP 제외)

- 회원가입 / 로그인 / 데이터 영구 저장 (DB)
- 플랫폼 API 자동 연동 (파일 업로드만 지원)
- 광고 소재·CTR·CPC·CVR 등 광고 세부 분석
- 쿠팡·네이버 외 플랫폼의 공식 지원 (구조는 확장 가능하게 설계)
- 예측 / 자동 예산 조정

## 5. 사용자 시나리오

### 시나리오 1 — 월간 성과 점검
1. 사용자가 8월·9월 쿠팡, 네이버 판매/광고 파일 4개를 업로드한다.
2. 업로드된 파일 목록과 플랫폼·기간, 데이터 미리보기를 확인한다.
3. "분석" 버튼을 누르면 전체 KPI 카드(매출·주문·광고비·광고매출·ROAS)와 전월 대비 변화가 표시된다.
4. 플랫폼 비교 차트와 매출·ROAS 추이 차트를 확인한다.
5. 이상 신호(예: 광고비 증가 대비 ROAS 하락)와 AI 인사이트를 확인한다.

### 시나리오 2 — 자연어 질문
1. 사용자가 "광고 효율이 가장 안 좋은 플랫폼 어디야?"라고 입력한다.
2. AI가 질문을 `{"metric":"roas","group_by":"platform","sort":"asc"}`로 변환한다.
3. pandas가 실제 계산을 수행한다.
4. 화면에 결과 표와 함께 AI 설명(근거 / 확인 항목 / 행동 제안)이 표시된다.

## 6. 기능 요구 사항

우선순위: **P0** = MVP 필수, **P1** = MVP 권장, **P2** = 여유 시

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| F-UP-01 | 여러 개의 Excel(.xlsx) / CSV 파일을 한 번에 업로드할 수 있다 | P0 |
| F-UP-02 | 업로드한 파일 목록(파일명, 플랫폼, 기간)을 표시한다 | P0 |
| F-UP-03 | 업로드 데이터의 앞부분을 표 형태로 미리보기 한다 | P0 |
| F-UP-04 | 파일 개수·크기 제한을 초과하면 명확한 오류 메시지를 표시한다 | P0 |
| F-UP-05 | 파일을 개별 삭제할 수 있다 | P1 |
| F-UP-06 | 드래그 앤 드롭 업로드 | P2 |

### 6-2. 데이터 정규화 (C)

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| F-DN-01 | 쿠팡 컬럼(`총매출, 주문, 판매량, 광고비, 광고매출`)을 공통 구조로 변환한다 | P0 |
| F-DN-02 | 네이버 컬럼(`판매금액(순), 상품결제건수, 결제상품수량, 광고비용, 전환매출`)을 공통 구조로 변환한다 | P0 |
| F-DN-03 | 필수 컬럼 누락, 숫자 형식 오류, 빈 파일을 감지하고 오류를 반환한다 | P0 |
| F-DN-04 | 파일명 또는 컬럼 구조로 플랫폼을 자동 판별한다 | P1 |

### 6-3. KPI 및 비교 분석 (C)

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| F-KPI-01 | 전체 매출, 주문, 판매량, 광고비, 광고 전환매출, ROAS 계산 | P0 |

| F-KPI-03 | 전월 대비 매출·주문·광고비 증감률(%), ROAS 증감(%p) | P0 |
| F-KPI-04 | 플랫폼별 KPI 비교 | P0 |
| F-KPI-05 | 이상 신호 감지 (예: `ROAS_DOWN_WITH_SPEND_GROWTH`) | P1 |
| F-KPI-06 | 상품별 KPI 순위 | P2 |

| F-DB-02 | 플랫폼 비교 차트 (쿠팡 vs 네이버) | P0 |

### 6-5. AI 분석 (D)

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| F-AI-01 | 자연어 질문 → 분석 계획 JSON (`metric`, `group_by`, `sort` 등) 변환 | P0 |
| F-AI-02 | 계산된 KPI를 사람이 이해하기 쉬운 문장으로 설명 | P0 |
| F-AI-03 | 결과를 **근거 / 확인 항목 / 행동 제안**으로 분리해 제공 | P0 |

| F-AI-05 | 데이터에 없는 요인(광고 소재, CTR, CPC, CVR, 경쟁사 가격, 시장 상황)을 원인으로 단정하지 않는다 | P0 |
| F-AI-06 | LLM 호출 실패 시에도 KPI 결과는 정상 표시되고 AI 영역에만 오류 안내 | P0 |
| F-AI-07 | 분석 불가능한 질문에는 지원 가능한 질문 예시를 안내 | P1 |

## 7. 비기능 요구 사항

| 항목 | 요구 사항 |
|---|---|
| 성능 | 파일 4개(각 1MB 이하) 기준 KPI 결과 5초 이내, AI 인사이트 포함 20초 이내 |
| 정확성 | 동일 입력에 대해 KPI는 항상 동일 (결정적 계산) |
| 신뢰성 | LLM 장애가 전체 분석 실패로 이어지지 않음 |
| 보안 | LLM API 키는 서버 환경변수로만 관리, 프론트엔드에 노출 금지 |
| 개인정보 | 업로드 데이터는 요청 처리 후 서버에 저장하지 않음 |
| 가용성 | Vercel + Render 배포 URL로 외부 접속 가능 |

## 8. AI 응답 원칙 (예시)

**입력 (C의 계산 결과)**
```text
매출 +21.2% / 광고비 +28.0% / 광고매출 +22.4% / ROAS -14.2%p
```

**좋은 응답**
> 매출은 증가했지만 광고비 증가율(28.0%)이 광고매출 증가율(22.4%)보다 높아 ROAS가 14.2%p 하락했습니다.
> 현재 데이터만으로 광고 소재 영향은 확인할 수 없습니다. CTR·CPC·CVR 데이터를 추가 확인하는 것이 좋습니다.

**실패 응답**
> 광고 소재가 안 좋아서 ROAS가 떨어졌습니다. ← 데이터에 없는 원인 단정

## 9. 성공 지표

| 지표 | 기준 |
|---|---|
| KPI 정확도 | fixture 정답과 100% 일치 |
| 질문 해석 정확도 | 준비한 테스트 질문 세트의 90% 이상이 올바른 분석 JSON으로 변환 |
| 과잉 추론 | 테스트 세트에서 데이터에 없는 원인 단정 0건 |
| 시연 완주 | 업로드 → KPI → 차트 → 질문 → AI 인사이트 흐름이 배포 환경에서 중단 없이 동작 |

## 10. 제약 및 가정

- 개발 기간 5일, 4인 팀
- 입력 파일은 플랫폼 관리자 페이지에서 내려받은 원본 형식을 기준으로 한다
- 기간 단위는 **월(YYYY-MM)** 을 기본으로 한다
- 통화는 원(KRW) 단일 통화
