## 구현한 다섯 가지
1. **근거와 문장의 연결** — 계산 결과를 출처 경로·기간·대상·지표·값·단위로 묶는다. AI는 내부 `InsightSelection`의 ID만 선택하고, 서버가 최종 문장을 만든다. 다른 플랫폼의 숫자를 가져와 새 주장을 쓰는 생성 경로를 제거했다. 여러 경로에서 같은 근거가 들어오면 표시 문장은 중복 제거한다.
2. **사실/확인/행동/한계 구분** — summary/evidence는 계산 근거 문장, checks/actions는 해당 데이터와 신호에 허용된 점검 문구로 제한했다. 원인 단정이나 임의의 목표치를 모델이 직접 출력할 수 없다. 필요한 추가 자료는 limitations에 서버가 명시한다.
3. **답변 가능성 확인** — 이전 기간 없음, 계산 불가 ROAS, 연속되지 않은 비교 월, 신호 없음, 질문 결과 없음, 같은 범위의 상충 값 등을 확인한다. 실제 0과 결측값을 구분한다. 질문 결과 없음과 상충 값은 유료 호출 전에 차단한다.
4. **질문 조건 누락 방지** — 명시한 지표/분류/정렬/개수/연·월을 추출해 모델 계획과 대조한다. 현재 계약에 없는 플랫폼·상품 필터, 범위 기간, 여러 지표, 이익/CTR/CPC/CVR 등은 안내한다. 모델도 표현하지 못한 조건을 내부 unrepresented_constraints로 반환한다.
5. **실제 품질 평가** — 질문 30개(지원 15, 미지원 15)의 기대 결과와 실행 도구, 인사이트 9개 시나리오를 마련하고 기존 버전과 비교했다.

## 기존 팀 작업과의 호환
- 최신 main과 비교해 B/C 구현, 공통 계약, 프론트엔드 변경 없음. API의 공개 Insight 필드와 상태 값은 유지한다. 기술문서는 D의 AI 설명 부분만 별도 커밋으로 동기화한다.
- 계산·새 지표·플랫폼별 변화율을 D가 별도로 구현하지 않는다.
- 내부 LLM 생성 스키마만 InsightSelection으로 바뀐다. 기존 InsightDraft/InsightContent는 호환 타입으로 남긴다.
- 질문이 미지원이어도 기존 B 흐름대로 계산 KPI가 유지된다.
- 기존 숫자 형식 검증 테스트는 NumberGrounding 자체의 회귀 검증으로 보존한다. 현재 생성 경로의 신뢰성은 근거 선택·서버 렌더링 테스트로 검증한다.
- `store` 전용 지표는 현재 B 호출에 들어오지 않으므로 해당 지표 질문을 지원한다고 표시하지 않는다.
- 원래 작업 폴더의 미커밋 WU-AI-04 작업과 GitHub PR #10은 그대로 둔다.

## 범위와 남은 한계
- 잘못 계산된 입력 자체를 일반적으로 검산하는 기능은 아니다. 동일 범위 결과 간 모순은 감지하지만 원본 누락/셀 오류까지 확인하려면 C의 품질 정보가 필요하다.
- 정확한 엑셀 셀/파일 출처는 현 계약에 없어 표시하지 않는다. 현재 근거는 계산 결과 경로와 기간/대상/지표다.
- 임의 자연어의 모든 조건을 규칙으로 완전히 해석할 수는 없다. 알려진 조건의 결정적 검사와 모델의 조건 점검을 함께 사용한다.
- 최종 문구는 자유 생성보다 표현 범위가 좁다. AI가 중요 근거를 선택하고 검증된 문구로 표시하는 의도적인 설계다.
- 기존 llm_error 상태를 유지하므로 계산 결과 불일치에 대한 전용 화면 메시지는 추후 B/A와 논의할 수 있다.
- 배포 화면 전체 E2E와 팀 최종 승인은 별도다. GitHub 게시와 실제 main 병합·배포 완료를 구분한다.
