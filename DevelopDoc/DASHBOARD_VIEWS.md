# 플랫폼 대시보드 표시

## 사용자 동작

- 첫 분석 뒤 기본은 간단보기. 쿠팡과 네이버 스마트스토어를 나란히 표시하고, 모바일에서는 세로로 배치한다.
- 매출액·광고비를 크게, ROAS·전월 수치와 증감을 함께 표시한다. 표시 이름은 판매 자료의 정의를 따른다.
- 자세히보기는 공통 지표·월별 추이·상품별 성과와 스마트스토어 전용 지표·구매 퍼널을 추가한다.
- 각 플랫폼은 독립적으로 접는다. 제목·기간·짧은 매출/광고비 요약은 남는다.
- 새 대시보드는 분석 후 바로 간단보기를 표시한다. 매출/광고 분석 버튼은 지표 순서를 바꾸는 자세히보기에서만 표시한다. 구버전 응답은 기존 모드 선택을 유지한다.
- 모드 변경·접기에서 API를 재호출하지 않고 채팅도 보존한다. 성공한 재분석은 모두 펼치고 정보량 선택은 유지한다. 실패한 재분석은 이전 결과와 접힘 상태를 유지한다.
- AI 요약은 본문/오른쪽 고정 열 대신 `AI 분석 요약하기` 플로팅 버튼으로 연다. 이미 생성된 결과를 보여 주며 열기·닫기에 API를 호출하지 않는다. 구버전 응답 화면에서도 차트 영역은 전체 너비를 사용한다.
- 요약 창은 닫기·돌아가기·Escape·배경 클릭으로 닫는다. 키보드 초점은 창 안에서 순환하고 닫으면 버튼으로 돌아온다. 파일 변경 시 이전 분석 기준을 안내하며, 요약 오류·분석 중·미제공 상태를 그대로 구분한다.
- 하단 대화창은 요약 버튼 위의 `AI 물어보기` 버튼으로 연다. 닫아도 대화·작성 중 질문·진행 중 요청은 유지하며, 전송할 때만 기존 API를 사용한다. 성공한 재분석 시 기존 정책대로 대화 기록을 비운다.
- 첨부파일 목록과 미리보기를 함께 접을 수 있다. 파일 개수·분석 버튼·월 누락 안내는 유지하고, 접힌 상태에서도 월 입력을 위해 목록을 펼칠 수 있다.
- 전체/플랫폼 요약과 KPI 수치는 가운데 정렬한다. 설명·대화와 상세 표의 정렬은 가독성을 위해 유지한다.

## 계산과 자료 정의

`analysis/dashboard.py`는 normalizer의 비공개 출처 기록으로 화면용 집계를 만든다. 기존 `kpis`, `comparison`, `rows`, `store`, AI 계획·답변은 변경하지 않는다. 기존 빈 셀의 0 정규화와 달리 화면용 지표는 원자료 빈 셀/대시를 null로 보존한다. 지표를 제공한 행 중 하나라도 빈 값이면 부분 합계를 완전한 합계처럼 표시하지 않는다.

기준 월은 전역 `kpis.period`, 비교 월은 달력상 바로 전월이다. 기준 월이 없는 플랫폼도 업로드 월과 자료 없음 상태로 남긴다. 전월 없음, 전월 0, 양수가 아닌 비율 분모는 계산 불가다. 비율은 합계에서 계산하고 %p 변화는 반올림 전 값으로 계산한다.

네이버 요약은 기존 `core_rows`와 동일한 중복 제거 규칙을 적용한다. 별도 SALES 상세는 그 원자료의 정의를 유지하며, 통합 템플릿과 겹치는 달에는 요약과의 차이를 안내한다. 광고매출은 매출액에 더하지 않는다. 기존 규칙 밖의 중복 파일 판별은 이번 변경 범위가 아니다.

쿠팡 원본 판매·광고는 검증된 같은 옵션 ID만 상품별로 결합한다. 통합 템플릿과 원본은 상품표에서 구분한다. 네이버 광고 소재와 스마트스토어 판매 상품은 분리한다. 상품표는 자료 종류별 상위 10개와 전체 개수를 명시하며, 총매출(스마트스토어), 광고비(네이버 광고), 매출(그 외) 순이다. 수치가 없으면 뒤에 놓고 동률은 ID 순이다.

전체 요약은 해당 지표가 모든 플랫폼에 있을 때만 합계를 표시한다. 플랫폼 일부가 판매/광고 자료를 올리지 않았거나 기준 월 자료가 없으면 알려진 값만 더해 전체처럼 보여 주지 않는다. 따라서 기존 KPI가 빈 셀을 0으로 처리해 합계를 반환한 경우, 새 화면은 불완전함을 표시할 수 있다.

## 호환성과 검증

새 서버 응답의 선택적 `dashboard` 블록을 사용한다. 블록이 없는 구버전 서버나 기존 mock 응답은 이전 화면으로 돌아간다. 새 기능 확인은 실제 API 모드에서 수행한다. 서버와 프런트의 배포 버전이 다르면 새 보기가 아직 표시되지 않을 수 있다.

`backend/tests/test_dashboard.py`는 2개월·2플랫폼 정답, 출처별 지표 유무, 빈 값/대시/0, 전월 누락·연도 전환·0 분모, 중복 제거, 상품 ID 분리, 순위·상위 제한, API와 AI 실패 독립성을 검증한다. 로컬 UI 검증은 실제 API 업로드부터 간단/자세히보기, 독립 접기, 키보드, 모바일, 채팅 유지, 추가 요청 없음까지 수행한다.
